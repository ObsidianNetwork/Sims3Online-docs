# Evidence schema catalog

`schemas/` contains 43 tracked JSON files: 39 JSON Schema documents and four example documents. They define analysis, validation and archive artifacts; they are not player/server wire schemas. See the [protocol reference index](../protocol-reference/index.md) for message contracts.

## Validation and use

`tools/native_observatory/evidence_schema_validation.py` loads schema files from `schemas/evidence/` and validates documents used by campaign reporting, archive checks and event streams. `tools/native_observatory/compare_runs.py` also loads Draft 2020-12 schemas to validate run comparison inputs. Archive construction and verification check required manifests, seals, reports, bindings and adjudication documents. Focused test entry points include `scripts/native_observatory_schema_test.py`, `scripts/native_observatory_archive_test.py`, `scripts/native_observatory_compare_test.py`, `scripts/native_observatory_anchor_test.py` and `scripts/native_observatory_toolchain_test.py`.

The inventory below reports each schema's title, required top-level members and property names/types from the current source. Nested `$ref`, `enum`, pattern, bounds, and conditional rules remain authoritative in the JSON file.

## Schema families and interpretation

- **Identity/toolchain:** analysis identity, effective profile, analyzer inventory, toolchain verification and synthetic smoke identity bind outputs to an input/toolchain context.
- **Static/native observations:** binary inventory, static export, symbol catalog, signature scan and event envelope represent bounded observations and provenance.
- **Managed/native relationships:** artifact inventory, managed boundary/call edge/mapping, registration, taxonomy and anchor map record candidate relationships, confidence and evidence references. They are not behavioral proof by themselves.
- **Execution/gates:** campaign report, preflight, gate, test execution, schema validation, safety, reproducibility and confirmation queue record checks and results.
- **Publication/adjudication:** source manifest, archive manifest/seal, analysis bindings and adjudication inputs/results close the identity and integrity chain.

Schema-valid JSON can still be semantically wrong, incomplete, unauthorised or based on mismatched inputs. Validators add cross-file identity, ordering, hash, path and gate checks beyond JSON Schema. Do not weaken a schema to make a producer pass; trace the field contract and update the producer, validator and tests.
